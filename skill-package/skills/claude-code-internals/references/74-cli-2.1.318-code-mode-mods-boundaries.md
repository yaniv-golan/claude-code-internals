# LESSON 249 — CODE MODE: ONE TOOL THAT RUNS JAVASCRIPT, WITH HOOKS STILL APPLIED PER CALL

**Code Mode is new in 2.1.318 and not in the changelog. The model's tool list collapses to `REPL`, `Poll` and `StructuredOutput`, and every other tool is reached from JavaScript. It does not bypass hooks or permissions: `PreToolUse`, rules and `canUseTool` run for each inner call under the inner tool's name. What changes is that a script never prompts as a script, and in auto mode the classifier reads a script once. It is off by default: an env var, a server gate and a one-time consent are all required.**

## Turning it on

- **The variable:** `CLAUDE_CODE_EXPERIMENTAL_CODE_MODE`, from flag settings, `~/.claude/settings.json` or the shell. Project and local settings aren't opt-in sources.
- **The gate:** `tengu_rustling_blossom`, default false, and it must arrive from a payload or override, not the disk cache. Absent from this machine's cache.
- **Consent:** a one-time dialog stores `codeModeCaveatsAcceptedV1` and `codeModeAutoModeCaveatAcceptedV1` in `~/.claude.json`, then relaunches the process, which checks everything again.
- **An admin blocks it** by setting the variable off in a managed tier or with a bare `REPL` or `Eval` deny. Managed settings can block it but not turn it on (inferred from the code paths).

It is refused, in order, for:

1. Not the native build.
2. No Bash.
3. `CLAUDE_CODE_REMOTE`, an entrypoint other than `cli`, non-interactive runs.
4. Background sessions, teammates, Remote Control.
5. Demo setups.
6. `--restricted`, or tool lists and deny rules that exclude `REPL`.
7. The engine check.
8. Agent teams.
9. A provider other than first-party on a first-party URL.
10. `apiKeyHelper` or custom auth headers.
11. HIPAA or ZDR.
12. `CLAUDE_CODE_ENABLE_TELEMETRY`, because Code Mode doesn't yet send an event per tool call.
13. Any model other than `claude-opus-5-5` and `claude-sonnet-5-5`.

## What the model sees

- **Tools:** `REPL` (shown as "Code", alias `Eval`), `Poll` and `StructuredOutput`. Every MCP tool and all others are hidden, and their names aren't sent to the API.
- **Globals in the script:** `$` (a shell tagged template that throws on a nonzero exit), `edit`, `write`, `preview`, `console`, `tools.<name>`, `tools.list()`, `searchTools`, `describeTool`. MCP is reached through `searchTools`. The full set is in the next section.
- **The engine:** Node `vm` inside Bun, a null-prototype context with code generation off, and no `import`, `require` or `process`. The context lasts for the session, not across restart, resume or fork.
- **Limits:** 600 seconds wall time including prompts, 30 seconds sync, 2 hours async, 30,000 characters per output part, 50,000 tool calls per script, 8 concurrent async evals.
- **Off in this mode:** Chrome tools, computer use and WrapUp.

## What it's for

The `REPL` tool description gives the model a cost model, and that is the clearest statement of purpose in the binary:

- **Calls are expensive, work inside a script is cheap.** Each `REPL` call is a full model round trip: the whole conversation is read again and the user waits. Shell commands, file reads, searches and tool calls inside a script cost comparatively little, and `Promise.all` runs them concurrently. So the model is told to gather everything the next decision could need in the script it is already writing, and to come back only when the next step depends on a result.
- **The worked example** searches for a function's definition and its callers in parallel, stops if nothing defines it, edits the defining file, then returns the callers and starts the tests, all in one call.
- **What a script returns stays in context; the rest doesn't.** Values left in variables stay in the REPL for later scripts to slice or search, so the model is told to return only what it needs to read now. `console` output goes to a ring outside context, and large shell output goes to a spill file.
- **Waiting is cheap.** A `Poll` with nothing to deliver ends just before the prompt cache would expire. A `Poll` sent in the same turn as a `REPL` call waits on that script, so a long build or test run costs no extra round trip.

**Our reading of the expected effect (not measured):**
- fewer model turns per multi-step task;
- slower context growth, so compaction comes later;
- long builds and test runs no longer hold up the conversation.

The gain should be largest for work that touches many files or tools, and small for a single edit or a question. Anthropic hasn't announced the feature or published any numbers.

## The script globals

The model gets them as TypeScript declarations inside the `REPL` tool description. The binary holds four zstd-compressed files, `core.{bash,powershell}.{sync,async}.d.ts`, plus two plain `team.{sync,async}.d.ts`. `Do()` picks one core file by shell and by whether the async lane is on, then appends an `interface Tools` built from the session's tools.

- **`$`:** a tagged template, or `$(cmd, timeoutMs)` for a plain string. Each `${}` value is single-quoted as one argument (an array gives one per item, `${{raw: s}}` splices unquoted), so quotes written around `${x}` remove that protection. Chainable `.nothrow()`, `.throws()`, `.quiet()`, `.timeout()`, `.cwd()`, `.env()`, `.text()`, `.lines()`, `.json()`, plus `$.escape`.
  - stderr is merged into stdout.
  - Exit 1 from a line ending in `grep`, `rg`, `find`, `diff`, `test`, `[`, `git diff` or `git grep` doesn't throw; `note` gives the reading.
  - A command is awaited for up to 600,000 ms by default, at most 7,200,000 ms. Past its timeout it moves to the background (one starting with `sleep` is stopped instead): the await resolves with `exitCode: null` and `running: {taskId, outputPath}`.
  - Large output spills to a file (first 64 MiB). The result also carries `truncated`, `whole`, `withheld` (a `PostToolUse` hook replaced it), `error` and `unsandboxedRetry` (the sandbox blocked the first run).
- **`edit(path, old, next, {all, soft})`** and a batch form taking `[old, next]` pairs. It's an exact match, so `$&` and the like aren't expanded. The batch checks every anchor before writing, and `soft` returns `{ok:false, error}` instead of throwing.
- **`write(path, content)`** (creates directories), and **`file(path)`** with `text`, `json`, `lines`, `exists` and `slice(offset, limit)`.
- **Output:**
  - `log(...)` returns lines with the result;
  - `console.*` writes to a bounded ring that stays out of context, read with `console.tail(n)`;
  - `preview(value, n)` cuts a value to `n` characters (200 by default), and for a spilled `$` result gives the size and the file path.
- **Also:** `sleep`, `self` (`globalThis`), timers that are cleared when their script ends, `atob` and `btoa`. `searchTools(query, max)` returns name, summary and input type; `describeTool(name)` returns the full schema.
- **Async lane only:** `running()` lists scripts still holding work, with `abort()`. A command moved to the background is no longer the script's work, and `abort()` doesn't stop it.

**Contexts (built, unreachable in 2.1.318):**
- **The API:** the `team` declarations add `spawnContext({name, role, initialPrompt, fork})`, `releaseContext`, `listContexts` and `contexts.<name>`, with `status`, `tail(n)`, `result()` and `log(text)`. `contexts.lead` is the main thread. A context going idle, failing or being released sends a `<task-notification>`.
- **What it calls:** `spawnContext` calls the `Agent` tool, with `subagent_type: "fork"` when `fork` is true. `releaseContext` calls `TaskStop`, and `log` calls `SendMessage`. So each call passes the same per-call hooks, rules and auto-mode refusals as any inner call.
- **Why it's unreachable:**
  - the runtime installs these globals only when `ic()` is false;
  - `Do()` appends their declarations only when `ic()` is false and the session holds `Agent`;
  - in 2.1.318 `ic()` and `ae()` both return the Code Mode consent flag, and the `REPL` tool is enabled only when `ae()` is true.

  So neither the globals nor their declarations reach a script. They're scaffolding for a REPL mode separate from Code Mode.
- **A prompt extract** that lists these declarations shows text shipped in the binary, not a feature a script can use.

## Hooks and permissions

**The outer `REPL` call:** in default mode its permission check returns allow, so a script never prompts as a script, and it never offers an always-allow rule. In auto mode it goes to the classifier with the code as input.

**Each inner call,** in order:

1. Call cap, input schema and validation.
2. The `PreToolUse` runner under the **inner tool's name**, so a `Bash`, `Edit` or `mcp__` matcher fires. Deny, ask, allow, `updatedInput` and `additionalContext` all work, and `continue:false` halts the script's later calls.
3. The rule check, then `canUseTool` with `replScriptCall:true`. Prompts appear per call. A denial comes back into the script as an error.
4. The tool runs.
5. `PostToolUse`, which can rewrite the output.

**Failure is stricter here.** A `PreToolUse` hook that times out is normally non-blocking. Once a REPL context exists, a timed-out hook refuses the call, and for inner calls a failed hook with no verdict also refuses.

**Auto mode, local classifier:** a script is classified once. An inner call rides that verdict only if the script was classified, nothing unclassified has run in the shared context, and the script hasn't returned. Other calls go to the per-call classifier, except read-only MCP calls and Bash commands spelled out literally in the script.

**Auto mode, server classifier:** riding is off. `Agent` and `SendMessage` from a script are denied, a command composed at run time is refused, a script rewritten by a hook is refused, and a Unicode escape sequence in the code is refused.

**Mods:** a mod that checks tool calls refuses Code Mode at startup, and a later one refuses the inner call (L250).

## For hook and skill authors

- A matcher on `Bash` or an MCP tool keeps working. Whether a hook on `REPL` can usefully see inner calls wasn't settled.
- A skill that tells the model to call a tool by name still works only if the model maps it to `tools.<name>`. That mapping is the prompt's job.

## Not traced

- The live gate value on other accounts.
- The PowerShell declaration files beyond their shared shape. The sync bash file is the async one without `running()`.
- What will make `ic()` differ from `ae()`, which is what would expose contexts.
- One classifier option branch.

# LESSON 250 — MODS: JAVASCRIPT PLUGINS THAT RUN INSIDE THE CLAUDE CODE PROCESS

**A mod is a plugin with a JavaScript hooks module, the machinery L187 calls function hooks. Installed mods are on by default now, and they run in a `Worker` thread inside the Claude Code process, with the person's own access. Mods that Claude writes in a session load only after a consent prompt.**

## What a mod is

A plugin with `hooks/register.ts`. The built-in `plugin-authoring` skill describes it as a change to Claude's own interface or behaviour: a pane, band, status line, toast, slash command, or a hook on tool calls. The API includes `$.env`, `$.model.fork`, and hook ids such as `tool.call`, `tool.check`, `prompt.submit`, `turn.step` and `classic.*`.

## Where it runs

In a `Worker` thread named `hooks-<8 hex>` inside the Claude Code process, not a subprocess and not a sandbox. The consent text says a mod runs with the person's own access.

## What gates it

- **Rollout:** `tengu_plugin_hooks_modules`, default **true**, and true on this machine. The switch can unload installed mods mid-session; built-in mods keep running. `CLAUDE_CODE_ENABLE_FUNCTION_HOOKS` has no reader in 2.1.318, only allowlist entries.
- **Off under:** `--bare`, safe mode and `disableAllHooks`.
- **Exclusions:** the claude-code-server tenant and the tool-server daemon.
- **Policy:**
  - `allowManagedHooksOnly` and `disableAllHooks`;
  - `pluginConfigs["cc-plugin-sec-default@builtin"].options.allowManagedModsOnly` limits mods to the organization's;
  - a mod can't override a deny rule unless `allowModsToOverrideDenyRules` is set.
- **Limits on a mod:** its env writes can't set `LD_PRELOAD`, `DYLD_*`, `NODE_OPTIONS` and similar.

Organization mods load regardless of the person-side hold, and a turn can wait for them.

## Mods Claude writes in a session

Mods under the config home's `dev-mods` folder hot-reload only after the prompt "Turn on the mods Claude writes in this session?" (`mod_hot_reload`, person-only, options How does this work?, Turn them on, Not now).

- **Refused without asking** for: diskless runs, mods off, `disableAllHooks`, `disableSideloadFlags`, blocked local directories, managed hooks only, safe mode, bare mode and an untrusted workspace.
- **Decline** means written but not loaded for the session. Loaded mods keep running.
- **From 2.1.318** the answer is shown as a virtual question and answer. Whether that record reaches the transcript file wasn't traced.

## With Code Mode

Mods that check tool calls refuse Code Mode (L249). The list covers `tool.call`, `tool.check`, the `classic.*` tool and permission events, `agent.offer`, `agent.spawn`, `session.send`, and task, elicitation and worktree events. An unreadable module counts as checking. Built-in plugins are excluded.

## Not traced

- What arms the `dev-mods` watch.
- The worker's isolation beyond the above.
- Whether a mod can override a Desktop forced ask (L187).

# LESSON 251 — NEW BOUNDARIES: BLOCKING WRITES, THE RM WAIVER AND THE PRIVACY CHECK

**`permissions.blockWritesOutsideWorkingDirectories` (2.1.314) refuses file-tool writes outside working directories in every mode. `CLAUDE_CODE_EVEN_MORE_DANGEROUSLY_SKIP_PERMISSIONS` (2.1.311, not in the changelog) waives one check, and any managed setting turns it off. A built-in check asks before an account email leaves through a network tool.**

## `blockWritesOutsideWorkingDirectories`

- **Refuses** `Write`, `Edit` and `NotebookEdit` outside working directories, in every mode. `true` in any settings source wins, and no allow rule lifts it.
- **Exempt:** plan files, the scratchpad, the background job folder, and this project's auto-memory, unless a repository settings file points it elsewhere.
- **Also:** refuses file-tool writes to Claude Code settings files even inside working directories, and removes `EnterWorktree` and `ExitWorktree`.
- **Doesn't limit** shell, MCP, hook programs or memory tools. So it's a guard on file tools, not containment.
- **It latches for the session,** and a session with it on can't teleport.
- **Its read twin** is `blockReadsOutsideWorkingDirectories` (L237). `permissions.blockReadsExemptPaths` is read only from `--settings` and host-sent settings.

## The rm waiver

Bypass mode keeps a few checks that it can't skip. `dangerousRemoval` is the only one that can be waived.

**The variable** `CLAUDE_CODE_EVEN_MORE_DANGEROUSLY_SKIP_PERMISSIONS` allows the call only if all of these hold:

- the mode is `bypassPermissions` and the decision is an ask;
- no `PermissionRequest` hooks, no hook registration in flight, managed hooks known;
- `CLAUDE_CODE_CHILD_SESSION` unset, so a nested `claude` never gets it;
- **every managed source is empty**: remote, helper, plist, HKLM, HKCU, file, parent. A read error counts as not empty, so any managed configuration disables it;
- no `blockReadsOutsideWorkingDirectories`, and no deny or ask rule on Bash, Edit or Read beyond bare forms. This one latches off.

No settings file can set it, and a plugin's `$.env.set` is refused. Still not waivable: `isolatePeerMachines`, `restrictedMode`, `outsideReadsBlocked`, `connectorFileSend`, `unfinishedCheck`. Each waiver logs `permission_bypass_removal_prompt_waived`.

## `cc-plugin-privacy` (2.1.317)

A built-in `tool.check` on `WebBrowser`, `WebFetch`, `WebSearch`, `Bash`, `Monitor`, `PowerShell` and `Tmux`, with a network-verb pattern for shells. It returns ask. It's on by default, can be turned off only from trusted settings, and has gate `tengu_wise_newt` (default on). So a headless skill that posts the account email may stall (inferred).

## Server-managed settings

From 2.1.316 (changelog), they apply without the security dialog when signed in with OAuth, the fetched org equals the current one and no profile store is in use, with any org pin matching and its JWS audience check passing (`first_party_silent`). Other cases still ask. A stored copy that fails verification is treated as absent. The check shipped in 2.1.314 but couldn't pass there: the function that reads the current org was a stub that returned nothing, so the org never matched. In 2.1.316 it returns the signed-in org's id, and only for a Team or Enterprise login (not through a gateway). That is the whole 2.1.316 change.

# LESSON 252 — WHAT ELSE CLI 2.1.311 TO 2.1.318 CHANGED

**A repeat `Read` now returns the file. `ultrathink` sets `xhigh` effort. Idle compaction lost its server flag. The default auto-mode allow list has 16 entries and one exception outside it. The model catalog reaches third-party providers. 2.1.316 gained an AOT-capable runtime, with no sign that Claude Code's own JavaScript uses it.**

## Changes to existing behaviour

- **Read (2.1.317):** no unchanged-file stub. A repeat `Read` returns the content and costs the tokens. Through 2.1.316 it could return a short "file unchanged" result (L8).
- **`Write` refuses a file it saw only part of** (changelog 2.1.312), a fourth failure mode beside the three in L8.
- **`ultrathink` (2.1.311):** typing the whole word, in any case, sets `xhigh` effort for the turn. `CLAUDE_CODE_DISABLE_ULTRATHINK` turns it off, then gate `tengu_turtle_carbon`, on here.
- **Idle compaction (2.1.314):** the server flag `tengu_sunny_locket` and `compact_on_return` are gone, and the values are constants: minimum 200,000 tokens, floor 100,000, fraction 0.9. `CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS` still overrides. It reports why it didn't run: `compaction_off`, `idle_compaction_off`, `precompute_compaction_off`, `swap_unsupported`, `prefix_changed`, `not_one_hour`, `lapsed`, `small`, `newer_request`, `near_limit`.
- **Auto-mode defaults (2.1.316):** `claude auto-mode defaults` prints 16 allow rules, not 17. "Scheduled-Task Fires" moved outside the replaceable slot, so an `autoMode.allow` without `$defaults` removes 16 rules and that one stays, and the command no longer shows the whole picture. A managed `allow` without `$defaults` now also holds against a host's `--settings`.
- **Model catalog (2.1.311):** `not_first_party` is no longer a plain rejection. `bedrock`, `vertex`, `foundry` and `mantle` can get it, `cloud_gateway` is its own outcome, and `not_claude_ai_auth` and `api_key_helper` pass subject to `allow_model_catalog`.
- **Sub-agent effort (2.1.316, 2.1.317):** `CLAUDE_CODE_SUBAGENT_EFFORT` applies only with no frontmatter `effort`, no fork and no inherited effort; `inherit` is accepted. Otherwise the agent's model's saved or default effort applies, not the session's.
- **Hooks:** `onFailure` (`continue` by default, `block`) on command and HTTP hooks from 2.1.295, SDK callbacks from 2.1.317; see L248 for the rule without Git Bash. Prompt and agent hooks are capped at 24 and 12 (changelog 2.1.312; constants `AIn`, `$0r`). `Monitor(tail *)` matches like a Bash rule.
- **Opus 4.8 fast mode** ends on 2026-11-30 (`tengu_sunset_penguin_opus48`).

## New, gated off or narrow

- **`WrapUp` (2.1.317):** a tool that takes `recap`, optional `ask` and `blocked`, and up to 2 `actions`, and fills the next-step box. It needs prompt suggestions on, and `CLAUDE_CODE_ENABLE_WRAP_UP` or a `remote` or `remote_desktop` origin with `promptSuggestions`. `tengu_merry_thunder` defaults on and is off on this machine.
- **`/project` (2.1.318):** sets the claude.ai Project for usage reports (`attributionProject`, `--save`, `clear`). Gate `tengu_gentle_cupcake`, default false. `CLAUDE_CODE_ATTRIBUTION_PROJECT` wins and a policy value blocks it.
- **`/use-case` (2.1.317):** a Life Sciences picker from server fields. Gate `tengu_federated_possum`, default false. `CLAUDE_CODE_PROGRAM_USE_CASE_ID` sets it.
- **Project thread rules in auto mode:** for a session that is a thread of a "Claude Code Project", the classifier gets a rule on member messages. A bare "yes" normally clears nothing. In the held modes it can answer the agent's last thread reply, if the harness checked that nothing newer intervened. The code default is the `original` rule; `tengu_projects_compact_thread_rule_enabled` defaults off and is on on this machine.
- **Betas:**
  - `tool-provenance-2026-10-26` (2.1.318), first-party, gate `tengu_snappy_noodle`, off here;
  - `claude-code-side-query-2026-09-29` (2.1.317), on side queries such as `generate_session_title`;
  - `program-use-case-ids-2026-09-17` (2.1.317), when a use-case id resolves.
- **New env, dark:** `CLAUDE_CODE_PERSONAL_HOOKS_OFF` (2.1.318, behaviour not traced), `CLAUDE_CODE_DISABLE_SUBAGENT_HANDBACK`, `CLAUDE_CODE_DISABLE_MCP_TASKS`, `CLAUDE_CODE_UPFRONT_TOOLS` (names tools kept out of deferral), `CLAUDE_CODE_AUTO_MODE_FULL_CONTEXT`.
- **Removed env:** `CLAUDE_CODE_LAZY_ENV_GETTERS`, `CLAUDE_CODE_TOOL_CONTAINER_PLUGINS_NAMED`, `CLAUDE_WORKSHOP_PROGRESS`.

## The runtime

2.1.316 added 25.9 MB of `__text`, the sections `__bun_aot` (3 KB) and `__bun_trim`, and AOT entry points such as `Bun__AOT__compile`. There's no evidence Claude Code's own JavaScript is compiled ahead of time: from 2.1.316 to 2.1.317 the payload grew 2.69 MB while `__text` grew 1,664 bytes and `__bun_aot` stayed the same size, and modules are still `// @bun @bytecode` in `__bun`. So the runtime gained the capability. The Bun version string stays 1.4.4 across four different commits, so pin the commit. `claude --version` timing showed no startup change. 2.1.316 also added `__info_plist` (`com.anthropic.claude-code`).

**The in-VM ELF 2.1.317** has the same `BUILD_TIME` and `GIT_SHA` as the host 2.1.317, and matching hit counts for the strings above.

## Not traced

- `deniedMcpServers` URL matching for Anthropic-provided servers (changelog 2.1.318).
- Which of the flags above are live on other accounts.
